# v6 Phase 6 — Reproducibility, comparison, and local research ledger

Status: implementation patch on the v6 working branch. The Yang–Mills Millennium Problem remains open. This phase improves reproducibility and review workflow only; it does not change the epistemic status of any mathematical claim.

## What changed

- Added a session-local research record ledger for the assumption, spectrum, and RG instruments.
- Every captured observation stores scenario/model/content identities, exact inputs, derived values, assumptions, regime, and T0 scope.
- Canonical scientific state receives a stable digest; capture time is excluded from that digest so identical scientific states retain the same state identity.
- Individual observations also receive distinct capture IDs so the same state may be recorded more than once without collapsing the run history.
- Added A/B comparison for records from the same instrument, including numerical deltas, assumption changes, and regime transitions.
- Added an exportable local JSON ledger and contextual copy output. No remote account, telemetry, or backend is introduced.
- Added a threshold-event log that records regime transitions already generated by the Phase 5 threshold engine.
- Added a review-packet copy action that carries the selected record's model/state context into the existing scientific-review workflow.

## Scientific-integrity constraints

- A record is evidence of what the interface calculated/displayed under declared inputs, not evidence that an H1 bridge is true.
- Comparison is T0-only and cannot promote a claim to E1 or establish a continuum theorem.
- The threshold-event log records interface regime changes, not physical phase transitions.
- Session records stay in browser `sessionStorage`; exports occur only by explicit user action.
