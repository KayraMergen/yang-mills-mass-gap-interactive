# Scientific Review Protocol

Scientific objections are welcome and should be formulated so they can be
audited independently.

A useful review should identify:

1. **Target** — exact node, lemma, definition, equation, source mapping, or UI claim.
2. **Type** — mathematical error, missing hypothesis, source/provenance error,
   terminology issue, or overclaim.
3. **Minimal counterexample / failure mode** — when applicable.
4. **Downstream impact** — which proof-chain nodes are invalidated.
5. **Evidence** — primary source, derivation, or explicit calculation.
6. **Proposed resolution** — correction, downgrade of epistemic status,
   additional proof debt, or removal.

The project should prefer a clearly labeled unresolved issue over silently
patching a scientific gap with intuition.
